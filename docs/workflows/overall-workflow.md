# 全体ワークフロー

## 概要

画像診断、カタログ参照、費用・工期・補助金、CRM連携を、既存のリフォーム相談フローに組み込んだ全体像です。

## フロー図

```mermaid
flowchart TD
    A[相談開始] --> B[AIヒアリング]
    B --> C[リフォーム箇所・希望内容を整理]
    C --> D{現状写真はある？}

    D -- ない --> E[写真撮影・アップロードを案内]
    E --> F[現状写真をアップロード]
    D -- ある --> F

    F --> G[画像診断]
    G --> H[部位別の状態・劣化度を表示]

    H --> I{診断結果をどう活用する？}
    I -- 素材を探す --> J[カタログ・素材参照]
    I -- 施工後イメージ --> K[施工後イメージ生成]
    I -- 概算を見る --> L[費用・工期・補助金を算出]

    J --> M[候補素材を選択]
    M --> K
    M --> L

    K --> N[ビフォーアフター確認]
    L --> O[概算費用・工期・補助金候補を確認]

    N --> P{内容を修正する？}
    O --> P

    P -- はい --> Q[箇所・素材・条件を変更]
    Q --> J
    P -- いいえ --> R[提案内容を確定]

    R --> S[提案書・PDFを作成]
    R --> T[担当者へ相談]

    T --> U[CRMへ案件登録]
    S --> U
    U --> V[担当者が案件を確認]
    V --> W[商談・現地調査へ]
```

## 利用者から見たメインの流れ

```text
相談
→ 写真アップロード
→ 画像診断
→ 素材選び
→ 施工後イメージ
→ 費用・工期・補助金確認
→ 提案書作成
→ CRM登録
→ 担当者対応
```

## 設計方針

- 画像診断は写真アップロード後に案内する
- 診断結果から、素材・画像生成・概算のいずれにも進める
- 画像診断は基本導線に含めるが、ユーザーがスキップできる余地を残す
- 素材・診断・概算の結果は、最終的に提案内容へまとめる
- 担当者への相談や提案書作成を、CRM登録につなげる

## レビュー項目

- 画像診断を必須にするか、スキップ可能にするか
- カタログ、画像生成、概算の順番は適切か
- 提案書作成とCRM登録の順番は適切か
- 途中で別の部屋・部位へ切り替えられる必要があるか
- 担当者へ引き継ぐタイミングは適切か
